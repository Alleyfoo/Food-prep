### Butter has states now (`79ea137`)
The user pointed out that brown butter is not an ingredient you buy — it is
what butter becomes when its milk proteins are held on heat. The ontology had
`butter`, `brown_butter`, `ghee`, `garlic_butter` as four unrelated
ingredients and **no butter state at all**, which is the project's own
category error: broccoli got four states, butter got none.

Butter is now `kind: both` with two transformations that are **opposite moves
on the same part of it**: `brown` cooks the milk proteins, `clarify` removes
them. That is why they are not interchangeable and why ghee keeps for months.
`brown_butter` and `ghee` remain filler ingredients as well — the cabbage /
sauerkraut two-entry shape — so existing pairings still resolve.

`garlic_butter` → **`garlic_confit`** (alias kept): the user's is whole cloves
slow-roasted ~2h in ghee, which cannot brown. Dimensions corrected
pungent → aromatic.

**The same question is open for other compound fillers.** If brown butter was
a state wearing an ingredient's clothes, check the rest before trusting them.

### 🎉 The first tasting is recorded (`7095799`)
**Brown butter on roasted broccoli — verdict `works`.** The first physical
result in the project. The "one ingredient, two truths" milestone and the
**README rewrite are no longer blocked** (Phase 8's exit condition is five
recorded tastings; this is one).

Recording it exposed a gap worth knowing about: trials only ever lived in the
**gitignored** database, and the app builds in memory from YAML every start —
so a trial was invisible in the UI and lost on a fresh clone.
`_preserve_tasting_trials` only protected a rebuild of an existing local file.
Trials now live in **`src/foodprep/data/tastings.yaml`**, loaded like every
other fact, and the file is **append-only**: if a second attempt disagrees,
add a second trial rather than editing the first.

The trial was later **annotated, not rewritten** (append-only): the verdict
stands, but what it lost to is garlic *confit*, not garlic butter — browned
proteins against no proteins, not two seasonings of one fat.

Two things the record deliberately does not say: it was a normal meal, not a
controlled test, so ratio and temperature read "not measured" rather than
borrowing the protocol's numbers. And **garlic butter gets no trial** — it is
already a Cook pairing at high confidence, never a hypothesis, and
`tasting_trials` requires an `analogy_id`. Only hypotheses can be tried; the
comparison lives in the brown butter trial's observations.

Note: any test that rebuilds with a stripped-down ontology must pass
`tastings_path=None`, because the loader refuses to drop a real kitchen
result when its hypothesis disappears.

### Two traps for the next agent
1. **Only the active tab renders now.** Streamlit garbage-collects the state
   of any widget it did not draw, so **every new input widget needs an
   explicit `key=`** *and* an entry in `_STICKY_WIDGETS` (or a
   `_STICKY_PREFIXES` match for dynamically keyed ones).
   `tests/test_ui_state.py` parses the app and fails if you forget.
   **Never persist a button key** — Streamlit then refuses to build the
   button, and it only bites on the *second* visit to that tab.
2. **Do not use `st.pills`.** AppTest cannot serialize a single-select pill
   group (it walks the value string character by character) and every
   subsequent `.run()` throws — it would cost the whole smoke-test workflow.

### Taste Circle Map rebuilt (ADDENDUM-2, in the bundle)
Q1–Q3 were answered, so tab 10 is done: the fan stays on the circle (the rail
is a **read-out, never a picker** — that is what distinguishes tab 10 from tab

**Two deviations from the written spec, both forced by measurement — tell the
designer if they matter:**
1. The arc cannot be both 110px and hold fourteen pills; fourteen need ~10×
   that arc. Radius is capped where the graph stays legible and a page holds
   whatever fits (5–6). Pages therefore **vary in size** — paging walks the
   offsets, it cannot assume a fixed stride.
2. `shapeProperties.borderRadius` must be ~half the pill height. vis folds the
   corner radius into the node's **bounding box**, so a CSS-style `999`
   reported a 2000px-wide node and `fit()` zoomed the graph to 0.25 (14px
   labels rendered at 3.6px). Pinned by a test.

### Third trap: Streamlit's markdown margin (`dd3970b`)
Streamlit hangs `margin-bottom:-1rem` on every `stMarkdownContainer` to
cancel a trailing `<p>`'s margin. **Our custom HTML ends in `<div>`s**, so
that -1rem ate 16px out of whatever followed — eight blocks were clipped and
the availability heading sat behind its own multiselect. Cancelled in
`design.css` for containers that do not end in a paragraph. If a new custom
block ever overlaps the next element, this is why.

**Rationale**:
- Current approach provides good UX: users see graph state and interact via intuitive buttons
- Custom component would take 18-36 hours for marginal improvement
- Adds maintenance burden and deployment complexity
- Works reliably on Streamlit Cloud without additional build steps

**Alternatives considered**:
1. Custom Streamlit component (React/TypeScript) - rejected due to complexity
2. streamlit-agraph - simpler but less control than pyvis
3. streamlit-echarts - more chart-focused than graph-focused

## Product direction (decided 2026-07-18)

The focus is a small catalogue of items actually buyable at the user's local
Lidl, turned into interesting foods, balanced food ideas and prepped
components — NOT Nordic cuisine, and not corpus expansion. The catalogue
(pinned in `tests/test_catalogue.py`): broccoli, rutabaga, greens (salad),
corn, tomato, avocado, kale, cucumber, mango, apricot, peach.

Expansion order for full journey treatment (one per session, to the broccoli
quality bar: distinct states, ≥2 destinations, ≥2 flavour routes, risks, ≥1
Scout hypothesis): **rutabaga → cucumber → kale → stone fruit
(peach/apricot/mango)**. Availability stays hand-curated; no scraping until
the catalogue outgrows manual upkeep. The existing classification layers
(roles, availability classes, Cook/Scout, verdicts) are considered sufficient.
