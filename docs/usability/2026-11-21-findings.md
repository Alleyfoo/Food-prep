## Findings

Severity: **high** = gives a wrong answer or blocks the task · **medium** =
misleading or slows the task · **low** = polish.

### High

1. **T1 — The availability filter contradicts the rest of the app.**
   With yogurt, lemon and garlic entered, every broccoli branch lists garlic
   and yogurt under "No match here". Yet broccoli's first journey is
   "stir-fried stems with soy and garlic", and its routes include *soy and
   garlic* and *creamy and acidic*. The filter only reads single-filler
   pairings, never routes. → **Fixed:** branch cards show the routes from that
   state that use what you have, and an item a route uses is no longer also
   listed as unpaired on the same card.
2. **T2 — A "rich" plate never hears "don't add more fat".** The avoid list
   appeared only at an average heaviness of 4 ("heavy"). Mashed potatoes plus
   a chickpea patty average 3.5 ("rich"), which is exactly the stodgy plate in
   the task. → **Fixed:** the avoid list starts at "rich"; the "leans heavy" risk
   stays at 4.
3. **T5 — The record command breaks in PowerShell.** It used `\` line
   continuations, which only bash understands. → **Fixed:** one line, which
   works in any shell.

### Medium

4. **T1 — "No match here" reads as "doesn't go with this".** It means no
   pairing has been recorded. → **Fixed:** "Not paired here yet".
5. **T2 — The heaviness KPI showed the plate's sum (7) with no scale**, next
   to a label computed from the average. → **Fixed:** it shows the average on
   the 0–5 scale ("3.5 / 5 · rich").
6. **T4 — "Too rare to tell" claimed "both sides are uncommon"** on roasted
   cabbage, one of the commonest ingredients there is; only brown butter is
   rare. → **Fixed:** the text explains the expected count without blaming
   both sides.
7. **T4 — "Other candidates" could not be clicked.** Reaching miso meant
   pressing "Next hypothesis" without knowing the order. → **Fixed:** each
   candidate is a button.
8. **T5 — "Record a tasting" is the primary button but records nothing.**
   → **Fixed:** "How to record a tasting".
9. **Data — smashed roasted potato had `heaviness_score: 6`** on a 0–5
   scale. → **Fixed:** 3 (between roasted and fried), and the loader now
   rejects scores outside 0–5.

### Low

10. **T3 — "Component — an after-state" is jargon.** → **Fixed:** "Something
    you already cooked".
11. **T4 — "The analogy is roasted broccoli with olive oil"** on a cabbage card
    reads like a mistake. → **Fixed:** "Reasoned from a known pairing: …".
12. **T1 — The next pick in "What do I have" can vanish.** Each pick reruns
    the page, and afterwards the box sometimes loses keyboard focus, so the
    next item typed goes nowhere. Clicking the box again before typing
    always works. This is Streamlit's multiselect and was seen on 1.50. Not
    fixed; mentioned so a tester recognises it, and worth re-checking on each
    Streamlit upgrade.
13. **Medium-high confidence showed as "MEDIUM_HIGH".** → **Fixed.**

## Not fixed — needs a decision

- ~~**Recording tastings from the app.**~~ Decided and built the same day:
  Scout has a *Record a tasting* form that appends to `tastings.yaml`. The CLI
  now appends there too; before, it wrote only to the local database, so
  CLI-recorded trials never reached the app.
- **Only 3 flavour routes.** Finding 1's fix surfaces routes where they exist,
  but most states have none, so for most ingredients the contradiction just
  becomes silence.
